## 1. 背景与总体架构

知识库全量外置 RAGFlow。nl2sql 后台「知识库」tab 目前只有最简转发（配置+勾选库+单文件上传），要升级为完整管理页；同时使用方要求：**日常操作知识库的人不该碰到 RAGFlow 连接配置（api_key / server 地址）**，因此引入第二个账号做权限隔离。

```
┌─ nl2sql（页面+后端一体） ──────────────────────────────┐
│ 管理后台「知识库」tab（升级为完整管理页）                  │
│   ├ 连接配置区：base_url / api_key（仅 admin 可见可改）    │
│   └ 管理区：库列表 / 文档管理 / 上传(本地+EAM) / 启停 / 进度 │
│ 账号体系（auth 升级为多账号）                             │
│   ├ admin：全权（现有单账户语义不变）                      │
│   └ kb_op（知识库操作员，新增）：只能进知识库 tab，          │
│      连接配置不可见，其余 tab 全部锁定                      │
│ 后端新增/扩展                                            │
│   ├ RagflowClient：文档启停等（见 4.1）                   │
│   ├ admin_ragflow 扩展 + admin_eam 新增                   │
│   └ 接口角色校验：kb_op 只放行知识库管理端点               │
└────────────────────┬────────────────────────────────────┘
                     │ 同一 RAGFlow 账号（nl_cfg_ragflow 表既有连接，不变）
                     ▼
             ┌──────────────┐
             │   RAGFlow    │  （启停/建库/上传都落在 RAGFlow，无自建状态表）
             └──────────────┘
```

**要点**：管理页面与 nl2sql 检索（knowledge_search）天然同源同账号——启停即时影响检索范围（默认全部库，见第 6 章）。RAGFlow 仍是唯一事实源，nl2sql 除账号外不新增任何数据表（EAM 对接配置走 yml、dqtoken 前端透传，见 4.4）。

## 2. 目标与非目标

**目标**

1. nl2sql 后台「知识库」tab 升级为完整管理页（入口不变，无需新菜单）
2. 新建知识库（选解析方式，默认通用）
3. 上传文档（**唯一上传入口**）：来源二选一——**本地文件 / EAM 文档树**；目标库可多选——同一文档一次进多个库（各库独立一份）；RAGFlow 不支持的格式自动拦截（本地）或隐藏（EAM 树）；解析进度展示（文件级进度条 + 库级汇总，3s 轮询）
4. 文件级启用/禁用开关；库级启停 = 批量翻转库内全部文件（覆盖式，不记忆单文件状态）
5. EAM 打通（上传弹窗的「EAM 文档管理」来源）：只读浏览 EAM **文档树** → 勾选文件或整个文件夹（子树全选）→ 选目标库同步（后端拿 dqtoken 逐个下载 → 传 RAGFlow → 自动解析）；同一文件可进多个库，不去重
6. **多账号与权限**：新增「知识库操作员」账号——登录后只能进知识库 tab 管理知识库；**RAGFlow 连接配置（api_key / server 地址）对其不可见不可改**；其余后台 tab 全部锁定
7. nl2sql 检索：默认全部库（去掉「勾选参与检索的知识库」勾选），启停即时生效

**非目标（明确不做，防蔓延）**

- 不做 EAM 定时自动同步 / 增量比对
- **绝不向 EAM 发任何写请求**（只读红线）
- 不做同步去重（同名中性提示，不拦截）
- 不做按库差异化检索参数（top_k / 相似度门槛仍是全局一份）
- 不做完整 RBAC（就两个角色：admin / kb_op，写死；以后要细分再说）
- kb_op 的鉴权粒度到 tab 级即可，不做到按钮级（连接配置整卡隐藏就满足了「不能动 apikey/地址」）
- EAM 对接配置进 yml 不进表；**除可能的账号存储外不新增任何数据表**（账号走 yml，见 4.4）

### 3.2 状态 × 启用 二维语义（写死防歧义）

`run`（解析进度）和 `enabled`（启用开关）是**两个独立维度**：

| | enabled=on | enabled=off |
|---|---|---|
| **run=DONE** | ✅ 参与检索 | 已解析但不召回（行置灰） |
| **run=RUNNING** | 解析完成后才可召回 | 解析完也不召回（行置灰） |
| **run=UNSTART** | 未解析，不可召回（「解析」按钮） | 同左，行置灰 |
| **run=FAIL** | 不可召回，红色进度条 + 悬浮看失败原因 + 「重新解析」 | 同左，行置灰 |

### 3.3 开关语义

- **文件级开关**（每行 Switch）：点击 → 调启停接口（单文件）；off 的行整体置灰（antd Table `rowClassName` + CSS opacity .5）
- **库级开关**（库列表每行 Switch）：`Modal.confirm` 提示「将把该库 N 个文件全部禁用/启用，覆盖现有单文件开关状态」→ 批量接口 → 刷新①②。**不记忆**：再启用时之前单独禁掉的文件也会被一起打开（已确认）
- 库开关显示态 = 该库全部文件 enabled 的聚合（全 on 才显示 on）

### 3.4 进度与轮询

- RUNNING 进度条（`Progress` 组件，`progress×100%`，蓝色）；DONE 绿色满格（`status="success"`）；FAIL 红色（`status="exception"`，悬浮 Tooltip 显示 `progress_msg`）；UNSTART 灰字「未解析」
- 轮询：任一库解析中或选中库存在 RUNNING 文档时，每 **3s** 同刷①（`GET /datasets?include_parsing_status=true`）与②（`GET /datasets/{id}/documents`）
- 停止：无 RUNNING / 组件卸载（`useEffect` 清理函数清定时器）/ 切换选中库 / 10 分钟上限（留手动「刷新」）
- 上传 / EAM 同步成功后立即手动刷一次并启动轮询

### 3.6 前端实现方案（React + Ant Design，已确认）

**组件映射**（页面 = 一个函数组件 + hooks，antd 组件全覆盖，无自定义UI）：

| 界面元素 | antd 组件 | 说明 |
|---|---|---|
| 库列表 / 文档列表 | `Table` | `rowClassName` 控选中/置灰行；`onRow.onClick` 点库名切换 |
| 文件/库级开关 | `Switch` | 受控组件，loading 态防连点 |
| 进度条 | `Progress`（line, size="small"） | RUNNING 蓝 / DONE `status="success"` / FAIL `status="exception"` |
| 状态/汇总徽标 | `Tag` | `color="processing/success/error/default"` |
| 失败原因悬浮 | `Tooltip` | 包文件名，显示 `progress_msg` |
| 新建库/上传/EAM 弹窗 | `Modal` + `Form` | 库级启停确认用 `Modal.confirm` |
| 来源切换 | `Radio.Group`（本地文件 / EAM 文档管理） | 切换上传弹窗内的来源面板 |
| 上传 | `Upload`（`beforeUpload` 返回 false 手动控）+ `Checkbox.Group` 选目标库 | 多文件×多库，前端逐库调用；不支持格式前端拦截 |
| 同步/上传结果清单 | `List` | 成功✓/失败✗ + 原因 |
| 提示 | `message.success/error` | 原型里的 toast |

**进度条实现**（对应 3.4；注意是**解析进度**不是上传进度——RAGFlow 后台异步解析，HTTP API 无推送，前端 3s 轮询文档列表拿 `run/progress/progress_msg`）：

```jsx
// ① 进度列：Progress 按 run 状态渲染
const ProgressCell = ({ doc }) => {
  if (doc.run === "UNSTART") return <span style={{ color: "#999" }}>未解析</span>;
  if (doc.run === "FAIL")
    return <Tooltip title={doc.progress_msg}>   {/* 失败原因悬浮 */}
      <Progress percent={Math.round(doc.progress * 100)} size="small" status="exception" />
    </Tooltip>;
  return <Progress percent={Math.round(doc.progress * 100)} size="small"
                   status={doc.run === "DONE" ? "success" : "active"} />;  // active=蓝色动画条纹
};

// ② 轮询 hook：hasRunning 由数据推导，依赖数组自动启停
export function useParsePolling(hasRunning, refresh, interval = 3000, maxMs = 10 * 60 * 1000) {
  const fnRef = useRef(refresh); fnRef.current = refresh;   // 拿最新闭包
  useEffect(() => {
    if (!hasRunning) return;
    const t = setInterval(() => fnRef.current(), interval);
    const stop = setTimeout(() => clearInterval(t), maxMs); // 10 分钟兜底
    return () => { clearInterval(t); clearTimeout(stop); }; // 卸载/无 RUNNING 自动清
  }, [hasRunning]);
}

// ③ 页面接线：一个 tick 并行刷「库汇总 + 当前库文档」
const refresh = useCallback(async () => {
  const [dss, docs] = await Promise.all([
    api.get("/datasets?include_parsing_status=true"),          // 每库计数一次带全
    selected ? api.get(`/datasets/${selected}/documents`) : Promise.resolve([]),
  ]);
  setDatasets(dss); setDocs(docs);
}, [selected]);

const hasRunning = docs.some(d => d.run === "RUNNING") || datasets.some(d => d.running_count > 0);
useParsePolling(hasRunning, refresh);
// 切库 / 上传·同步成功后手动 refresh()：新文件立刻以 RUNNING 出现，进度条接管
```

**状态管理**：单页面无需全局 store——`useState`（库列表/文档列表/选中库/EAM 树勾选）+ 项目既有 request 封装。

**antd 版本差异**：主蓝 v4 `#1890ff` / v5 `#1677ff`，用法一致；以资产哨兵项目 package.json 为准。

**接入方式**：新页面走资产哨兵既有微前端/路由接入（URL 带 `/saas/micro/` 为子应用挂载），左侧菜单项由平台菜单配置添加。

**原型说明**：[原型-知识库管理.html](原型-知识库管理.html) 为零依赖手写版，视觉按 antd v4 形态复刻，仅用于交互评审，不是实现基线。

## 4. 资产哨兵后端接口设计（新增模块）

> 形态对齐 nl2sql 参考 `admin_ragflow.py`：REST 转发 + 统一错误处理、后端无状态；连接配置全部走后端配置文件（见 4.4 零新表方案），页面不提供 RAGFlow 连接编辑入口。

### 4.1 RAGFlow 转发接口

| 端点 | 说明 |
|---|---|
| `GET /datasets?include_parsing_status=true` | 库列表（含每库 done/running/fail 计数） |
| `POST /datasets` body `{name, description?, chunk_method?}` | 建库（默认 naive=通用） |
| `GET /datasets/{id}/documents?page=&page_size=` | 文档列表（run / progress / progress_msg / enabled） |
| `POST /datasets/{id}/documents` multipart `file`（可多文件） | 上传文件；多目标库时前端逐库调用 |
| `POST /datasets/{id}/parse` body `{document_ids:[...]}` | 触发解析（对应 RAGFlow POST /datasets/{id}/chunks） |
| `DELETE /datasets/{id}/documents` body `{ids:[...]}` | 删除文档 |
| `PUT /datasets/{id}/documents/enabled` body `{document_ids?, enabled}` | **单文件/整库启停统一端点**（ids 缺省=全库）；后端循环调 RAGFlow `PUT /datasets/{ds}/documents/{doc}`，逐项容错，返回 `{total, updated, failed:[{id,name,error}]}` |

### 4.2 EAM 接口（同域优势）

| 端点 | 说明 |
|---|---|
| `GET /eam/documents?keyword=`（header/body 带 dqtoken） | 代理 EAM 列表（只读，无后端存储）；token 失效 → 401 + 「dqtoken 已过期，请重新粘贴」 |
| `POST /eam/sync` body `{dqtoken, items:[{id,name}], dataset_ids:[...]}` | 同步（见 4.3 时序；dqtoken 前端透传） |
| EAM 配置 | 连接信息（base_url / list_api / download_api）在**资产哨兵后端配置文件**；**dqtoken 由前端每次请求透传**（body 带），后端不存储 |

**同域优势**：资产哨兵后端与 EAM 同在 saas.gw-greenenergy.com 域内，无跨域问题；若平台有服务间调用凭证可替代手工 dqtoken，抓包时一并确认（是则配置里去掉 dqtoken 字段）。

### 4.3 同步时序（单请求内，逐 (文件×库) 容错）

```
用户在文档树勾 N 个文件（M=1：目标固定为当前选中库，接口 dataset_ids 保持数组通用）→ POST /eam/sync
  aborted = false
  for 文件 f:                # ≤20 个（前端硬限）
    for 库 d:                # M 个
      if aborted: results += {f, d, ok:false, error:"dqtoken 已过期"}; continue
      try:
        name, bytes = EAM 下载(f.id)                 # 300s 超时
        RAGFlow 上传(d, name, bytes)
        RAGFlow 触发解析(d, [doc_id])
        results += {f, d, ok:true}
      except EamTokenExpiredError: aborted = true; results += {f, d, ok:false, error:"dqtoken 已过期"}
      except Exception as e: results += {f, d, ok:false, error:str(e)}，继续下一项
  return {results, ok_count, fail_count}
```

不搞后台任务：同步本身快（同域下载+上传），慢的是 RAGFlow 解析——解析进度由文档列表 3s 轮询自然展示。`# ponytail:` 单批经常超浏览器超时再升级 BackgroundTasks + 任务表轮询。

### 4.4 配置存储：零新表方案（资产哨兵侧不开任何表）

| 配置项 | 放哪 | 为什么 |
|---|---|---|
| RAGFlow base_url / api_key | 资产哨兵后端配置文件（yml/env/既有配置中心） | 长生命周期，改配置即可，无过期问题 |
| EAM base_url / list_api / download_api | 同上（后端配置文件） | 接口路径抓包后改一次配置就通 |
| EAM dqtoken | **前端 localStorage + 每次请求透传**（GET/POST 带上，后端只过境不落盘） | session 级短命凭证，本来就从浏览器来；后端零存储，重启/过期都无需运维介入 |

**全部页面功能都不需要自建表**：启停状态、解析进度、文件清单全部现查 RAGFlow（RAGFlow 是唯一事实源），资产哨兵后端是无状态转发层。

## 5. RAGFlow API 映射（两边通用）

| 功能 | 端点 | 关键请求 | 关键响应字段 |
|---|---|---|---|
| 列知识库 | GET /api/v1/datasets?include_parsing_status=true | — | document_count / chunk_count / unstart_count / running_count / cancel_count / done_count / fail_count |
| 建库 | POST /api/v1/datasets | `{name, description?, chunk_method?}` | dataset 对象（id） |
| 列文档 | GET /api/v1/datasets/{ds}/documents | — | run(UNSTART/RUNNING/CANCEL/DONE/FAIL) / progress(0~1) / progress_msg / chunk_count / **enabled** |
| 上传 | POST /api/v1/datasets/{ds}/documents | multipart `file=@`（可多文件） | document 对象（id, run=UNSTART） |
| 触发解析 | POST /api/v1/datasets/{ds}/chunks | `{"document_ids":[...]}` | code=0 |
| **文档启停** | PUT /api/v1/datasets/{ds}/documents/{doc} | `{"enabled": 0或1}`（int） | code=0 |
| 删除文档 | DELETE /api/v1/datasets/{ds}/documents | `{"ids":[...]}` | code=0 |
| 检索 | POST /api/v1/retrieval | `{question, dataset_ids, top_k, ...}`（**dataset_ids 至少一个，不传报错**） | chunks[] |

**页面功能 ↔ RAGFlow API 支持性对照（全部支持，零自建存储）**：

| 页面功能 | API | 支持性 |
|---|---|---|
| 库列表 + 解析汇总 | GET /datasets?include_parsing_status=true | ✅ 原生 |
| 新建库 | POST /datasets | ✅ 原生 |
| 文件列表 + 进度 | GET /datasets/{id}/documents（run/progress/progress_msg） | ✅ 原生 |
| 上传（多文件） | POST /datasets/{id}/documents multipart | ✅ 原生 |
| 触发/重新解析 | POST /datasets/{id}/chunks | ✅ 原生 |
| 文件级启停 | PUT /datasets/{id}/documents/{doc} `{"enabled":0\|1}` | ✅ 原生（旧版字段名 `status`） |
| 库级启停 | 无库级 API = 文件启停循环 | ✅ 组合实现（设计 4.2 决策 3） |
| 删除文件 | DELETE /datasets/{id}/documents | ✅ 原生 |
| 格式过滤 | RAGFlow 支持列表前端预过滤 | ✅ 无需 API |

**RAGFlow 支持的文件格式**（前端按扩展名预过滤，以部署版本实测为准）：pdf / doc / docx / xls / xlsx / ppt / pptx / txt / md / csv / json / jpg / jpeg / png / gif / bmp / tiff / epub。其余（zip / exe / dwg / cad 图纸等）在 EAM 树中隐藏、本地上传中拦截。

**版本兼容实测清单（上线前跑一遍）**：新版字段 `enabled`，旧版 RAGFlow 是 `status`——先用真实实例测：

```bash
# 1. 启停一个测试文档（报错则换 {"status":"1"}）
curl -X PUT "$RAGFLOW/api/v1/datasets/$DS/documents/$DOC" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" -d '{"enabled": 0}'
# 2. list 验证 enabled 已变
curl "$RAGFLOW/api/v1/datasets/$DS/documents?id=$DOC" -H "Authorization: Bearer $KEY"
# 3. retrieve 验证禁用后不召回
curl -X POST "$RAGFLOW/api/v1/retrieval" -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"question":"<该文档独有关键词>","dataset_ids":["'$DS'"]}'
```

封装时字段名收敛为一个常量，实测不过一行切。

## 7. EAM 适配（资产哨兵后端）与只读红线

- **只读红线：EAM 适配层只发 GET；sync 端点代码评审核对无任何对 EAM 的 POST/PUT/DELETE；页面不提供任何 EAM 编辑入口**
- 接口路径全部来自配置不硬编码 → **抓包后只改配置不改代码即可联通**
- **待抓包清单**（F12 → Network → Fetch/XHR，在 EAM 文档管理页操作）：
  1. 文件列表/目录树请求的 cURL + Response JSON（展开文件夹时触发）。**重点确认：是一次返回全量树，还是按目录逐级懒加载**（决定前端 Tree 用 treeData 直接渲染还是 loadData 懒加载）
  2. 文件下载请求的 cURL（预览或下载时；若先返回下载 URL 再 GET，两个都要）
  3. dqtoken 挂在哪个请求头
  4. （加分）平台若有服务间凭证可替代 dqtoken，一并确认

## 8. 边界与错误处理

| # | 现象 | 处理 | 用户看到的 |
|---|---|---|---|
| 1 | RAGFlow 旧版不认 `enabled` 字段 | 封装层常量一处切 `status`；按第 5 章清单实测 | 无感 |
| 2 | dqtoken 过期（401/登录页 HTML） | 专属异常中断同步（已传的保留，剩余标失败） | 红字「dqtoken 已过期，请从 EAM 重新复制粘贴」+ 输入框聚焦；结果清单失败项可重选 |
| 3 | 大文件同步慢 | 下载/上传独立 300s 超时；逐项容错不中断批次 | 单项失败原因在结果清单 |
| 4 | 批量启停部分失败 | 逐项容错返回 failed 明细 | 「已更新 14/15，1 个失败：xxx.docx（原因）」 |
| 5 | 重复同步/上传同一文件到同一库 | 不拦截不去重（支持同一文档多库并存），弹窗中性标注 | 「该库已有同名，将再添加一份」 |
| 6 | 解析失败 | FAIL 红条 + 悬浮 `progress_msg` + 「重新解析」 | 失败原因可见可重试 |
| 7 | nl2sql 存量：检索范围扩大到全部库 | 预期行为，发布知会 | 无感 |
| 8 | EAM 未配置/未抓包 | 端点返回 400「EAM 未配置」；页面隐藏 EAM 入口 | 无感 |
| 9 | 两边同时操作 RAGFlow（资产哨兵管理 + RAGFlow 控制台） | RAGFlow 是唯一事实源，页面每次现查 | 刷新即最新 |
